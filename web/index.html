How a reply finds its voice

AssemblyAI's text-to-speech speaks one language per session. A tutor reply mixes languages in every sentence, so the LLM tags them and the router gives each piece its own native voice.

Evaluation: how the tutor's speech-to-text handles learners

Each clip is a learner doing what this product's users do: asking about a word, or trying a phrase. It's streamed through AssemblyAI's real-time model at speaking pace with the tutor's exact settings. Click a row to see the transcripts; ▶ plays the recording.

Key finding: a deliberately wrong “bibliotica” comes back as “biblioteca” in every configuration tried, with word confidence 1.0, so the tutor would praise it. Speech-to-text tells the tutor which words were said, not how well: pronunciation grading needs its own model.

Ease of migration

For a customer already on LiveKit Agents (Pipecat has equivalent AssemblyAI support), switching to AssemblyAI changes three things. Their prompts, tools, UI and telephony stay as they are.

1 · Speech-to-text

Swap the STT plugin

stt=assemblyai.STT(
    model="assemblyai-stt-3-7-realtime-agent",
    language_codes=["en", "es", "fr", ...],
)

End-of-turn detection comes with it: AssemblyAI's model decides when the learner is done.

2 · LLM

Change the address the LLM calls

llm=openai.LLM(
    model="gemma-4-31b",
    base_url="https://llm-gateway.assemblyai.com/v1",
)

LLM Gateway speaks the OpenAI format: same client, new address, the same API key as STT and TTS.

3 · Text-to-speech

Swap the TTS plugin

tts=assemblyai.TTS(
    model="assemblyai-tts-1",
    voice="aai-kyla",
)

One voice per language, from AssemblyAI's catalog.

The one part that isn't a config swap: AssemblyAI's text-to-speech speaks one language per session, and a tutor's reply mixes languages in every sentence. The native voice per language needs the routing module in this repo (language_tts.py, about 200 lines, built for this demo in an afternoon). It's reusable as is, so it ships with the migration rather than being rebuilt.
  • It also sends the KeepAlive the LiveKit plugin is missing, so idle voices don't disconnect (worth reporting upstream).
  • Rollout without risk: shadow mode first (AssemblyAI transcribes alongside the current provider, no user impact), then 5% of sessions, then ramp. Rolling back at any step is a config change.
